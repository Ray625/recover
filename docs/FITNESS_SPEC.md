# 健身紀錄網站規格草稿

狀態：第一階段本機版已實作，進行自動驗證；帳戶、同步與統計延後。
更新日期：2026-11-24。

通用基礎版已另外複製保留，直接在目前專案開發健身紀錄網站。以下保留已確認需求，並記錄本階段採用的實作預設。

## 已確認需求

### 頁面與入口

- 需要日曆、帳戶、統計、設定頁面，中央提供快速紀錄按鈕。
- 先完成紀錄流程；跨裝置與統計為後續必做功能，本階段不實作。
- 快速紀錄預設今天；若使用者已在月曆選定其他日期，則預設該日。
- 新增過程中仍可修改日期，因此可以補登。

### 兩種紀錄方式

使用 checkbox「逐組詳細紀錄」切換：

- 未勾選：簡略紀錄，只記大概重量與總組數。
- 勾選：詳細紀錄，每組分別記錄重量與次數，同一動作的各組可以不同。

例如詳細紀錄的啞鈴臥推：

| 組別 | 重量 | 次數 |
| --- | --- | --- |
| 1 | 左右各 10 kg | 12 |
| 2 | 左右各 12.5 kg | 10 |
| 3 | 左右各 12.5 kg | 8 |

簡略紀錄例如「啞鈴臥推，左右各約 10 kg，3 組」。此時沒有每組次數，也不表示每組都確定使用相同重量。

### 重量表示

- 各重：雙手拿啞鈴時，填左右手各自的重量，例如「左右各 10 kg」。不要求使用者換算成總重 20 kg。
- 共重：例如槓鈴，直接填總重。
- 保留重量表示方式，讓使用者回看紀錄時知道下次要使用或增加多少重量。
- 各重不代表左右側各做幾次，也不套用到槓鈴兩側槓片。

### 分類與動作

- 使用「大類 → 動作」兩層結構，例如「胸 → 啞鈴臥推」。
- 使用者自行選擇大類，並在裡面新增動作名稱；大類也能自行調整。
- 分類用途是快速找到動作與安排當日訓練，不需要精確表達每個動作涉及的所有肌肉。
- 第一版採動作隸屬一個大類的概念，不建置肌群多重標記系統。

## 整日／單項複製、操作選單與完成勾選

### 單項複製（已確認）

- 每項紀錄各自有三點選單，提供「複製」、「編輯」、「刪除」。
- 點選「複製」會開啟新增紀錄頁面，帶入該筆動作與完整簡略／詳細資料。
- 日期預設為實際今天，不跟隨月曆選定日期；新增過程可調整日期與內容。
- 完成狀態預設勾選，不繼承來源完成狀態。
- 使用者儲存後才建立新紀錄；取消新增不建立紀錄。

### 整日複製（已確認）

- 每日紀錄區的三點選單提供「複製課表」。
- 點選後開啟彈窗，選擇複製到哪一個日期，預設為實際今天。
- 確認後將來源日的全部動作紀錄及完整簡略／詳細資料複製到所選日期。
- 所有新紀錄的完成狀態一律未勾選，不繼承來源完成狀態。
- 取消彈窗不建立紀錄。
- 「課表」在此指來源日的整份動作紀錄，不表示另外建立獨立的課表模板系統。

### 共用規則（已確認）

- 單項與整日複製都建立獨立的新紀錄，後續修改不影響來源紀錄。
- 目標日期已有紀錄時追加，不覆蓋。
- 複製後可逐項調整重量、組數，以及詳細模式中的次數。
- 每項動作紀錄前直接顯示完成 checkbox，勾選單位是整項動作紀錄，不是每一組。
- 手動快速新增預設已完成，仍可取消勾選。
- 取消完成勾選只改狀態，保留紀錄內容。
- 未來統計只計入已完成紀錄；未勾選者保留為待做項目。

第一版實作預設：

- 允許重複複製，每次都追加，不額外彈出說明。
- 複製保留來源動作與分類快照，來源動作已刪除仍可複製；在新增表單選擇其他動作時，改用該動作的目前名稱與分類。
- 可以修改過去日期的完成狀態。
- 儲存或複製後，切換到目標日期。

當日選單先不預設加入清空整日等功能。

## 介面文案原則（已確認）

- 單項選單顯示「複製」，當日選單顯示「複製課表」。
- 目標日期由新增頁或日期彈窗處理，選單文字不加「到今天」等說明。
- 介面以簡短功能名稱、欄位標籤與必要的錯誤提示為主，不加入大量解釋性文字。

## 操作流程草案

1. 開啟日曆，初始選定今天，顯示當日紀錄。
2. 使用者可先選其他日期，再按中央快速紀錄。
3. 新增視窗以選定日期作為初始值，日期欄位可隨時修改。
4. 選擇大類，再選擇動作；若沒有適合的項目，可以新增。
5. 選擇各重或共重，填入簡略資料；勾選詳細紀錄時，改填每組重量與次數。
6. 儲存至表單上的日期，更新該日列表與月曆標記。

第一版儲存後關閉視窗並切換到目標日期；不預設連續新增。紀錄刪除需確認。

## 紀錄模式與資料規則

已確認的模式切換行為：

- 簡略轉詳細：依簡略組數產生各組，帶入原本重量，次數留空供使用者填寫。
- 詳細轉簡略：帶入第一組重量作為可修改的代表重量，組數採目前總組數。在同一次編輯視窗內暫存逐組內容，再次勾選詳細紀錄時可還原，避免切換造成重填。
- 儲存時以目前模式為準；隱藏的詳細草稿不當作有效紀錄保存。

第一版實作預設：

- 一筆紀錄代表某天的一個動作，可包含多組；同一天允許再次記錄相同動作，不自動合併。
- 新增預設簡略模式；編輯與複製沿用來源模式，不記住前次新增的模式。
- 簡略模式保存代表重量與組數，沒有逐組次數，不製造不存在的詳細組資料。
- 詳細模式保存各組重量與次數，組數由組別列數決定；可新增、刪除組別，或複製上一組。
- 各重／共重設在整筆紀錄層級，各組沿用同一表示方式。
- 簡略紀錄未來可計入訓練天數與組數；沒有完整次數，不納入精確的重量乘次數訓練量。
- 只支援 kg，允許小數；組數與次數為正整數。
- 徒手、輔助重量、單側動作次數與暖身組是否納入，留待需要時討論，不先自動推算。

## 分類與動作管理

已確認：

- 分類支援新增、查看、修改與刪除。
- 動作支援新增、查看、修改與刪除，並能移到其他分類。
- 每個動作只屬於一個分類，不提供無分類動作。
- 只有空分類可以刪除。分類內仍有動作時，禁止刪除，提示使用者先將動作移至其他分類。
- 刪除分類不連帶刪除動作或訓練紀錄，不提供連同動作一起刪除的選項。
- 動作搬移必須指定另一個現有分類；若沒有其他分類，使用者可先新增分類。
- 刪除動作後，過去訓練紀錄仍保留，包含當時的動作名稱、分類、重量、組數與已填寫的次數；不連帶刪除訓練紀錄。
- 動作或分類改名、動作移至其他分類時，舊紀錄保留當時的動作名稱與分類，不隨管理清單更新；新紀錄使用建立當下的名稱與分類。

第一版提供胸、背、肩、腿、手臂、核心及各一個常見動作作為可編輯的初始資料。

第一版提供分類換色與搜尋，分類、動作依建立順序排列；拖曳排序留待後續需求。不以封存取代刪除。

| 入口 | 內容 | 階段 |
| --- | --- | --- |
| 日曆 | 月曆、訓練日標記、選定日期的紀錄 | 第一階段 |
| 中央快速紀錄 | 開啟新增視窗，支援兩種紀錄模式與修改日期 | 第一階段 |
| 設定 | 主題、分類與動作管理 | 第一階段 |

底部排列：日曆、帳戶、快速紀錄、統計、設定。帳戶與統計保留入口，僅顯示「尚未開放」，不提供假登入或假統計。所有螢幕沿用相同的手機版配置，詳見下方版面原則。

## 版面原則（已確認）

- 手機版為主要設計與驗收目標。
- 內容區限制最大寬度並水平置中；螢幕更寬時，僅增加左右留白。
- 大螢幕仍使用相同的日曆、紀錄列表、底部導覽及中央快速紀錄配置，不切換成桌面側欄或多欄版面。
- 底部導覽與固定操作區對齊內容區寬度，不橫跨整個桌面螢幕。
- 新增頁面與彈窗延續手機操作流程，寬螢幕不另設一套介面。
- 小螢幕不應產生頁面水平溢位；底部操作需考慮手機安全區。
- 自動驗證以手機尺寸為主，並檢查寬螢幕的內容置中、最大寬度與操作一致性。
- 內容最大寬度採 480px；表單彈窗最大 440px。

## 暫定資料概念

資料模型位於 `src/domain/fitness.ts`，本機儲存位於 `src/stores/fitness.ts`。

| 資料 | 內容 |
| --- | --- |
| 大類 | 穩定識別碼、名稱、顏色；依建立順序顯示 |
| 動作 | 穩定識別碼、名稱、所屬大類 |
| 動作紀錄 | 識別碼、訓練日期、動作關聯、當時動作名稱與分類快照、完成狀態、簡略／詳細模式、各重／共重、建立與更新時間；動作刪除後仍可獨立顯示歷史 |
| 簡略資料 | 代表重量、總組數 |
| 詳細組別 | 排序、重量、次數 |
| 使用者歸屬 | 後續接入帳戶時加入；資料隔離與搬移規則另訂 |

訓練日期保存為當地日期（YYYY-MM-DD），與建立時間分開，避免時區轉換造成跨日。

第一階段採 localStorage 本機保存，提供 JSON 匯出／匯入。匯入驗證版本、識別碼、分類關聯、日期、重量與組別格式，確認後取代資料；取消或驗證失敗不修改既有內容。原有資料損壞時保留原始內容並阻止一般寫入，可匯出原始資料後匯入有效備份。跨裝置階段再接雲端，搬移與衝突規則於該階段規劃。

## 分階段範圍

### 第一階段：紀錄流程

- 日曆、選定日期與當日紀錄列表。
- 單項複製與整日複製課表、每日與每筆紀錄各自的三點選單、各項動作紀錄的完成 checkbox，以及複製後逐項調整。
- 快速新增，支援簡略／詳細 checkbox、各重／共重與修改日期。
- 大類與動作的選擇、新增與管理。
- localStorage 保存，JSON 匯出／匯入備份。
- 每筆訓練紀錄支援編輯與刪除，入口放在該筆三點選單；刪除前確認；未切換動作時，編輯保留歷史名稱與分類。
- 主題切換與偏好保存。

### 後續必做

- 帳戶、跨裝置與雲端保存；需包含第一階段資料的搬移規劃。
- 統計，明確區分簡略紀錄與詳細紀錄可提供的資訊。

### 暫不列入

獨立課表模板管理（整日複製已納入）、休息計時器、體重體脂、照片、飲食、有氧、社群與教練共享，除非後續討論追加。

## 驗證與後續

- Playwright 驗證手機與桌面 Chromium 的實際操作，並產生畫面截圖。
- 型別檢查、正式建置與 Lint 為基本檢查。
- Safari、手機實機、PWA 安裝與離線更新尚需另行驗證。
- 雲端登入、資料同步、統計與本機資料搬移留待下一階段。
